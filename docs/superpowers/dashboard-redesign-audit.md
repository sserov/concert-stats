# Design Audit — concert-stats dashboard (Stage 1)

Date: 2026-09-27. Scope: анализ текущего состояния; код не менялся.
Данные: `data/dataset.json` — 24 631 концерт, 12 сезонов (2015/16–2026/27),
москонсерватория 16 405 / филармония 8 226.
Скриншот «до»: `docs/screens/before/desktop-1440.png` (1440×900).

## 1. Критические дефекты текущей версии

1. **Дашборд фактически не работает.** В `dashboard_template.html` обработчик
   `document.getElementById('top').on('plotly_click', …)` вешается до первого
   `redraw()`, когда `#top` ещё не стал Plotly-плотом → `TypeError: .on is not
   a function` → `redraw()` не выполняется → все 4 графика пустые в любом
   браузере. (Пин CDN-версии Plotly ошибку не закрывал.) Воспроизведено
   headless-Chrome: JSERR на строке 167, SVG:0. После патча (redraw до
   биндинга) — 5 SVG, графики рисуются.
2. **Нет визуальной иерархии.** Четыре одинаковые карточки 2×2: главный
   вопрос пользователя (тренд репертуара по сезонам) визуально равен
   второстепенному покрытию данных.
3. **Доля не показывается вообще.** Все графики — абсолютные количества.
   Из-за роста охвата источников (409 концертов в 2015/16 → 3 469 в 2024/25)
   абсолютные тренды читаются как «рост популярности», хотя это рост охвата.
4. **Хитмап нечитаем.** 40 строк × Viridis (радуга), без подписей значений,
   без выбора метрики.
5. **Фильтры несинхронизированы.** Поиск фильтрует только top-bar; выбор
   композитора — только через dblclick по карточке тренда (не Discovery);
   heatmap и coverage на выбор не реагируют.
6. **Данные о неполноте скрыты.** Ничто не помечает: текущий сезон 2026/27
   (320 концертов, ~9% сезона), обвал meloman 2017/18 (52 концерта — провал
   Wayback), ковид 2019/20–2020/21. Пользователь неизбежно сделает неверные
   выводы из абсолютных чисел.
7. **Производительность.** Каждый redraw тренда пересканировывает 24 631
   запись × 5 композиторов × 12 сезонов в браузере; файл 16,3 МБ из-за
   инлайн-`program_text`.

## 2. Что данные говорят (факты для дизайна)

- **Топ-5 (доля всех концертов, все сезоны):** Чайковский 3 241 (13,2%),
  Рахманинов 2 661 (10,8%), Бах 2 237, Моцарт 2 024, Бетховен 1 988.
  Это дефолт для trend-чарта — стабильно, репрезентативно.
- **Юбилейный эффект реален и виден в доле, не в абсолютных числах:**
  Шостакович 3,2–4,5% в завершённых сезонах, но **10,3% в текущем 2026/27**
  (50-летие смерти — юбилейный сезон 2025/26 дал умеренные 4,3%, основной
  всплеск — старт юбилейного программирования 2026/27). Это ключевой story
  дашборда: его нельзя убить погрешностью охвата, потому что это доля.
- **Охват по залам:** консерватория полная с 2017/18 (1 327+); филармония
  достоверна только с 2018/19 (527), до этого Wayback-обрывки (2016/17 — 135,
  2017/18 — 52). Сезон 2015/16 усечён самим срезом данных (с января 2016) —
  **не полноценный сезон**.
- **2025/26 у филармонии подозрительно низкий** (719 против 1 375 в 2024/25) —
  частичный захват; аннотировать как «частичный охват».
- **Залы:** консерватория — 4 больших зала + музейные площадки; филармония —
  Филармония-2 (6 266) и КЗЧ (1 941). Сравнение залов = сравнение учреждений
  (source), не физических залов.

## 3. UX/UI Redesign Proposal

### Информационная архитектура (порядок скролла)

1. **Header** — заголовок, подзаголовок, одна строка описания, «О проекте».
2. **Sticky-контролы** — зал (segmented), диапазон сезонов (от/до), поиск с
   autocomplete, чипы выбранных (макс. 6).
3. **KPI-строка** — 4 значения тонкой строкой (не карточки): концерты,
   композиторы, покрытие программ, без композиторов.
4. **Главный чарт: «Как меняется популярность композиторов»** — 100% ширины,
   ~560px высоты, линии-доли, дефолт top-5. Единственный доминирующий элемент.
5. **«Кто звучит чаще всего»** — таблица с сортировкой и спарклайнами.
6. **«Репертуар по сезонам»** — heatmap, top-15 + «показать ещё».
7. **«Один композитор — два зала»** — сравнение залов для выбранного.
8. **«Насколько полны данные»** — coverage с аннотациями провалов.
9. Methodology note — рядом с coverage и в «О проекте».

### Визуальная иерархия

- Один доминант (trend), остальные секции — подсвечены только заголовком с
  тонкой линией-разделителем, без карточных рамок.
- Serif (Georgia) — только h1 и заголовки секций; всё UI/данные — system sans.
- Палитра из ТЗ; серии композиторов — 6 фикс. цветов (тёмный бордо, серо-
  зелёный, охра, приглушённый синий, коричневый, оливковый), НЕ Plotly-default.
- Heatmap: 3-стопный sequential #F7F5F0 → #D9A69B → #8C2635.

### Ключевые интеракции

- Любой выбор композитора (таблица / autocomplete / клик по линии / ячейка
  heatmap) → чип + линия в тренде + строка в heatmap + подсветка в таблице.
- Клик по линии/точке/строке heatmap → drawer карточки композитора (тренд,
  залы, юбилеи, сезоны, последние концерты).
- Метрика Доля/Количество — тумблер в тренде и heatmap; Доля — дефолт.
- Аннотации: юбилеи — компактные подписи у точек; ковид — бледная полоса
  фона 2019/20–2020/21; текущий сезон — пометка «(тек.)» + tooltip о неполноте.

### Типографика и адаптив

- Desktop-only (1440×900+, решение 2026-09-27); единственный breakpoint ~1200
  для паддингов; чарты `responsive:true`.
- Размерная лестница: h1 34px serif, заголовки секций 22px serif, UI 14px,
  данные в таблице 14px tabular-nums, подписи 12px muted.

### Производительность

- Все агрегаты предвычислены в Python (`AGGREGATES`): делители долей по
  сезону×залу, композитор×сезон×зал, юбилеи, coverage. Браузер только
  делит/форматирует. Slim-концерты (без program_text) для drawer-списка.
  Целевой размер файла < 4 МБ.

## 4. Отличия от ТЗ (на утверждение)

1. **Сезон 2015/16** — в данных есть, но он усечён (постановка среза с
   2016-01-01). Предложение: в контролах диапазона «От 2016/17» как в ТЗ;
   2015/16 доступен в выпадашке, при выборе — пометка «усечён данными».
2. **Аннотация покрытия расширена** против ТЗ: кроме «филармония до 2019 —
   частично» добавить «меломан 2025/26 — частичный захват» (719 против нормы
   ~1300) и «2015/16 — усечён срезом данных».
3. Story-акцент дефолтного тренда: top-5 по доле (Чайковский…Бетховен) —
   юбилейный кейс Шостаковича пользователь найдёт через поиск/таблицу; чипы
   подсказки не добавляем (YAGNI).

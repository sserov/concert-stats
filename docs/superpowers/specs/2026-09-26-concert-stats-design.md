# Concert Stats — дизайн

Дата: 2026-09-26

## Цель

Собрать статистику исполняемых композиторов в двух московских залах классической
музыки — Московская филармония (meloman.ru) и Московская консерватория
(mosconsv.ru) — за 10 лет (2016–2026), и построить статичный дашборд, на котором
видно, как композиторы входят в тренды (например, рост частоты в юбилейные годы:
Шостакович, Чайковский).

Проект личный, однопользовательский. Успех: открыл `dashboard.html` в браузере —
увидел тренды по композиторам с фильтрами по залу и сезону.

## Исходные данные (проверено probe-ом 2026-09-26)

### mosconsv.ru (Консерватория)

- JSON API `GET /api/concert/forday?date=YYYY-MM-DD` — список событий дня
  (id, время, зал, название, ссылка). Работает на любую историческую дату,
  включая 2020 и 2016.
- Страница концерта `/ru/concert/<id>` — полная программа с произведениями
  (server-rendered HTML). Старые id (проверено 2022, 2020) отдаются кодом 200.

### meloman.ru (Филармония)

- Живой архив на сайте отсутствует: афиша `/concert/` показывает только
  текущие события, URL-параметры дат игнорируются.
- Источник истории — Wayback Machine (web.archive.org):
  - CDX-индекс `meloman.ru/concert/*` — уникальные URL событий:
    2020 — 526, 2022 — 1492, 2024 — 2815. До 2019 покрытие реже.
  - Часть старых страниц событий жива на самом сайте (HTTP 200), остальные
    берём из снапшотов Wayback.
- Принятое ограничение: за 2016–2018 покрытие филармонии частичное (~30–50%
  пропусков). На дашборде отображать метрику покрытия по годам.

## Подход

Python-пайплайн: скрипты скрапинга → JSONL → датасет → генератор статичного
HTML-дашборда. Всё запускается вручную, скрапинг возобновляемый (кэш сырых
ответов), данные — файлы в `data/`.

Отвергнутые альтернатативы: Node/TS-пайплайн (парсинг кириллицы и HTML удобнее
в Python, дашборд всё равно статик); Jupyter (не воспроизводимый пайплайн).

## Компоненты

### scrape_mosconsv.py

1. Итерация дней с 2016-01-01 по текущую дату (~3650 запросов к
   `/api/concert/forday`).
2. Для каждого события — `/ru/concert/<id>` (~7–8k страниц).
3. Парсинг: дата, зал, название, текст программы.
4. Выход: `data/mosconsv/events.jsonl`, сырые ответы в `data/raw/mosconsv/`.

### scrape_meloman.py

1. CDX-запрос по годам (2016–2026): `web.archive.org/cdx/search/cdx?url=meloman.ru/concert/*`
   плюс исторические паттерны URL афиши, если обнаружатся при скрапинге ранних лет.
2. Для каждого URL: попытка живого fetch; при 404 — ближайший снапшот Wayback.
3. Парсинг: дата (из URL-слага и/или страницы), зал, название, программа.
4. Выход: `data/meloman/events.jsonl`, сырые ответы в `data/raw/meloman/`.

Вежливый скрапинг: задержка ~0.3 с между запросами, ретраи с backoff на 5xx,
User-Agent с контактной строкой. Повторный запуск пропускает уже скачанное
(проверка наличия в `data/raw/`).

### composers.py

- Курируемый словарь ~300 известных композиторов: канонический id, отображаемое
  имя, вариации написания (рус. сокращения «П. И. Чайковский», лат. транслит).
- Матчинг: поиск вариаций по тексту программы и названия + эвристика паттерна
  «И. О. Фамилия» в начале строк программы.
- Нормализация: одно событие → множество композиторов без дубликатов.
- Нераспознанные остатки с частотой выше порога → `data/review_unknown.txt`
  для ручного пополнения словаря. Процесс итеративный: прогон → просмотр хвоста
  → дополнение словаря → повторный прогон extraction (без перескачивания).

### build_dataset.py

- Мердж событий обоих источников, дедупликация (один источник — один зал,
  коллизий между залами не ожидается; дедуп внутри источника по id/URL).
- Сезон: сентябрь–июнь, метка «2025/26» (события июля–августа относятся к
  закончившемуся сезону).
- Выход: `data/dataset.json`:
  - `concerts[]`: `{date, venue, hall, title, composers[], program_text}`
  - `coverage`: счётчики событий по источнику и году (для пометки провалов).

### build_dashboard.py

Генерирует `dashboard.html`: данные встроены как JSON, графики Plotly (CDN).

Вьюхи:

1. Bar/treemap: топ композиторов за период, фильтр по залу.
2. Heatmap: композитор × сезон — юбилейные всплески видны как светлые полосы.
3. Линии: доля концертов сезона (%), где исполняется композитор, — тренды.
4. Справочник юбилеев (годы рождения/смерти композиторов из словаря) — маркеры
  на трендах (год юбилея подсвечен).
5. Фильтры: зал (филармония/консерватория), сезон, поиск композитора.
6. Блок покрытия: число событий по годам, чтобы видеть провалы данных
   (ковид 2020–21, слабый Wayback 2016–18 у филармонии).

Один файл, работает открытием из файловой системы, без сервера.

## Метрики

Единица учёта — концерт: композитор «исполнялся в сезоне», если есть хотя бы
один концерт с ним. Дополнительная метрика «число концертов с композитором»
(не число произведений — подсчёт произведений по грязным текстам программ
ненадёжен).

## Обработка ошибок

- Скрапер: сетевые ошибки — ретраи (3 раза, backoff), окончательная неудача —
  лог в `data/raw/<source>/_errors.log`, пропуск, продолжение. Итог отчёта:
  сколько ok / failed.
- Парсинг: неожиданная структура страницы — событие сохраняется с пустой
  программой и флагом `parse_failed`, попадает в счётчик качества датасета.
- Матчинг композиторов: неизвестные — в «прочие» + `review_unknown.txt`.

## Тестирование

- pytest: парсеры mosconsv/meloman на зафиксированных HTML-фикстурах (реальные
  страницы, сохранённые в `tests/fixtures/`), матчинг композиторов (вариации
  написания, «И. О. Фамилия», отрицательные случаи), сезонная принадлежность (дата → сезон,
  границы сентября/июля).
- Скраперы тестируются на фикстурах, не на живой сети.
- Проверка качества датасета: скрипт `build_dataset.py` печатает долю концертов
  без распознанных композиторов; цель < 10% после первой итерации словаря.

## Зависимости

`httpx` (HTTP + таймауты), `beautifulsoup4` + `lxml` (парсинг HTML). Всё
остальное — stdlib. Версии фиксированные (`==`).

## Объём и запуск

- ~25–30k запросов суммарно, несколько часов с задержками. Одноразовый полный
  прогон; дальше инкрементально (`scrape_*.py` докачивает только новое).
- `build_dashboard.py` перегенерирует дашборд за секунды.
